3.3. Etch-a-sketch#

In this portion of the lab, you will learn how to build a simple etch-a-sketch application using the SSD1306 LCD screen and two potentiometers.

3.3.1. Materials#

  • USB cable

  • Breadboard

  • Raspberry Pi Pico

  • LCD Screen

  • 2 Push Buttons

  • 2 Potentiometers

  • Wires

3.3.2. Getting Started#

  • Inside your lab3 folder, create another folder called etch-a-sketch.

  • Within the etch-a-sketch folder, place the main.py file that you downloaded earlier.

3.3.3. Hardware#

3.3.4. Step 1: Place the LCD screen on the breadboard#

Place the LCD display on the breadboard so that its pins align with four consecutive rows. Ensure that all the pins are inserted securely into the breadboard.

3.3.5. Step 2: Connect the LCD screen to the breadboard#

  • Connect the row where VCC is placed on the LCD screen to the 3.3V pin on the Pico using a wire.

  • Connect the row where GND is placed on the LCD screen to a GND pin on the Pico using a wire.

  • Connect the row where the SDA pin is placed on the LCD screen to GP16 on the Pico using a wire.

  • Connect the row where the SCL pin is placed on the LCD screen to GP17 on the Pico using a wire.

3.3.6. Step 3: Add the Potentiometers#

You will be using the potentiometer’s ADC values to draw on the screen. The coding portion will explain more in-depth on how the potentiometers allow us to draw on the LCD screen. But for now, place the potentiometers on the breadboard, one on either side of the screen.

  • Left Potentiometer: Connect to GP26

  • Right Potentiometer: Connect to GP27

The main.py file we provided uses GP26 and GP27 for the potentiometers ADC pins, but feel free to use any 2 ADC pins but remember to update the code in the file.

Refer back to lab2 on how to wire the potentiometers.

3.3.7. Step 4: Add the Switch Buttons#

The switch buttons will allow us to interact with the various menu options within the main.py file. Place two switch buttons on the breadboard, one on either side of the screen.

  • Option Button: Connect one side to GP19 and the other to GND

  • Select Button: Connect one side to GP20 and the other to GND

The main.py file we provided uses GP19 and GP20 for the GPIO pins, but feel free to use any two GPIO pins. However, remember to update the pin numbers in the main.py file.

Refer back to lab1 on how to wire the switch buttons.

3.3.8. Code#

You’ve finished the hardware set up so let’s move onto coding.

3.3.9. Step 1: Variable Declaration#

Start by declaring two constants called max_analog_value and min_analog_value. These two values will hold the max and minimum analog value of the potentionmeters.

Next, we need two constants for the height and width of the LCD screen used here which is 128x64

After that, initalize the I2C object and then an instance of the SSD1306-I2C class from the SSD1306.py file.

You should now be ready to handle user input and begin drawing to the screen.

3.3.10. Step 2: Input Setup and States#

After initallizing your LCD display, let’s initalize the various states that you’ll need to interact with the LCD screen.

First, initalize your two switch buttons and two potentionmeters.

Using the potentiometer readings, calculate the initial x and y position of cursor on the LCD screen. You will need to normalize the values using the min_analog_value and min_analog_value variables from step 1. Be sure to restrict the x and y positions so they fit on the LCD screen. Hint, you can use the max() function.

Next, you need to initialize a bytearray which is just an array of bytes to store the image data (aka what’s being shown on the screen) We will be sending this byte array to our LCD screen so it draws on the screen.

image = bytearray(0x00 for _ in range(16 * 64))

Afterwards, initalize the following variables to keep track of various states

  • drawing_mode (on/off): toggles between drawing mode or menu selection

  • eraser_on: toggles between drawing or erasing

  • clear_sketch: clears the LCD screen

  • quit_sketch: exits the program

  • show_cursor: allows us to have a visual cursor on the LCD screen

At this point, your screen should be blank, your cursor position should be set, and your variables ready to control the application’s behavior.

3.3.11. Step 3: Main Loop and Menu#

Wrap your program in a while true loop. This will keep your LCD screen on until you choose to quit.

Inside the while true loop, you need check if the menu button has been pressed:

Step 3.1: Creating the Menu#

Create a list of menu options that can handle the following: Eraser, Clear Sketch, Save, Load, Back, Quit

It’s will be up to you to determine the layout of this menu, but the fill_rect() function might be useful to show which menu option is currently selected. Here’s an example of this function:

oled.fill_rect(10, 10, 107, 43, 1)   # draw a solid rectangle from 10,10 to 117,53, colour=1

Step 3.2: Navigating the Menu#

If the option button is pressed, move the selection down the menu options. Wrap around to the beginning when you reach the end.

Step 3.3: Handling Menu Selection#

When the select button is pressed, check which menu option is current selected.

Depending on which one is currently selected, implement the following:

  • Toggle the eraser: switch between drawing and erasing mode

  • Clear the sketch: sets the flag, so that the screen gets cleared

  • Save the sketch:

    • Look for an available save slot (limit the number of saves).

    • If no slots are available, show an error message.

    • Otherwise, save the current image buffer to a file.

  • Load a sketch:

    • Check for available saved files.

    • Display a menu to pick a file to load.

    • Load the selected file into the image byte array buffer.

  • Exit back to drawing: leaves the menu options screen

  • Quit the application: exits the entire loop

3.3.12. Step 4: Drawing and Erasing#

Before drawing, you need to determine if you are trying to clear a sketch or not. Remember the image byte array we had? That is what we will be using to send to the LCD screen to display the image on the screen.

First, we should update our cursor position similar to how we got the cursor position at the start with the x and y values.

If your cursor has moved and you’re in drawing mode, you should update the image byte array to either draw or erase pixels.

  • Drawing: Set specific bits in the image to 1

  • Erasing: The opposite of drawing

(Tip: You can calculate which bit to modify based on the (x, y) pixel position. Think about dividing the width into groups of 8 pixels.)

Handing a 3x3 area: Instead of just drawing a single pixel, you may want to draw or erase a 3x3 block centered around the cursor for a thicker line. Note, this step is entirely optional but will make your sketch more visible.

Rendering the frame: After updating the image array, use a FrameBuffer object to display the updated image onto the screen. Framebuffer acts like a temporary canvas and organizes the image byte array into a format the LCD screen can display.

You can create a framebuffer object by passing in a byte array, width, height, and the format

frame = framebuf.FrameBuffer(image, WIDTH, HEIGHT, framebuf.MONO_HLSB)

After creating the framebuffer, you can draw it onto the LCD screen using

oled.blit(frame, 0, 0) # draws the image starting at 0,0 of the LCD screen

Cursor Display: If you want to show a cursor on the screen, you can draw it at the updated x and y position after rendering the frame.

Don’t forget to show everything at the end.
